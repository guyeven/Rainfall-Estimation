## Final plan summary (ready to code)

### CLI inputs (with validation prompts)

The program will prompt for:

1. Patch list JSONL (full path)
2. Patch attributes JSONL (full path)
3. 4TU links JSONL (full path)
4. Output directory (full path)
5. Number of patches (k) to process (integer)
6. Default polarization for missing pol **(allowed: H, V)**

   * We will print allowed answers in parentheses and keep prompting until valid.

Optional debug:
7) Debug mode? **(allowed: y, n)**
If `y`:

* patch id to debug
* link index (integer) within that patch output list

### Processing

For the first (k) patches in *patch-list order* after filtering to selected:

* Selected patches are those present in the attributes JSONL.
* Each patch contains full H5 path in `source_file` (no H5 directory prompt).
* Load and crop rainfall from its H5 file using existing approach.
* NaN → 0
* refine 2 km → 125 m by 16×16 inheritance
* Gaussian smoothing σ=1 refined pixel with `mode="nearest"`

Links:

* project 4TU endpoints to EPSG:28992
* translate by (t=P-Q) with (P) = patch NW corner transformed to EPSG:28992, and fixed anchor (Q) (from existing link filter code)
* keep only links with both endpoints inside the patch rectangle
* compute per-link attenuation by pixel intersections + ITU + dB sum

ITU:

* copy ITU function into new project
* frequency in JSON is **GHz**
* if frequency missing → use 10 GHz and print a message
* if polarization missing → use user default (H/V) and print a message

### Outputs

* Per patch id: one JSONL file containing all links in the patch with:

  * original link fields
  * `link_index` (record index in that file)
  * `attenuation_db`
* Debug output (on demand): JSON file named with patch id and link index containing per-refined-pixel trace.

### Input prompting requirement

For all prompts with limited choices (polarization, debug yes/no), the program will:

* show allowed answers in parentheses
* re-prompt until valid input
